# OctoAcme Project Management Documentation

Welcome to the OctoAcme Project Management process library. This documentation centralizes all project management guidance, workflows, and best practices used across OctoAcme.

## Overview

OctoAcme follows a structured, iterative project management approach designed to deliver customer value while maintaining clarity, accountability, and continuous improvement. Our methodology applies to all cross-functional projects that deliver product features, services, or integrations.

## Core Principles

- **Customer-first**: Prioritize customer value and usability in all decisions
- **Iterative delivery**: Deliver small, testable increments and iterate based on feedback
- **Clear ownership**: Each project has named Project Manager and Product Lead roles
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback, learning, and continuous improvement

## OctoAcme Project Lifecycle

All OctoAcme projects follow a five-phase lifecycle:

```
Initiation → Planning → Execution & Tracking → Release & Deployment → Retrospective & Continuous Improvement
```

### Phase Overview

| Phase | Purpose | Key Deliverables |
|-------|---------|------------------|
| **Initiation** | Validate business need and align stakeholders | One-pager, Stakeholder list, Initial risk list |
| **Planning** | Break work into actionable increments | Prioritized backlog, Release plan, Definition of Done |
| **Execution & Tracking** | Build, test, and track progress daily | Working software, Risk updates, Demo/Review |
| **Release & Deployment** | Deploy to production safely and reliably | Release notes, Deployment verification, Post-deploy monitoring |
| **Retrospective** | Capture learnings and drive continuous improvement | Action items, Documented learnings, Process improvements |

## Getting Started

**New to OctoAcme project management?**

1. Start with [Project Management Overview](octoacme-project-management-overview.md) for a big-picture view of principles and roles
2. Read [Roles and Personas](octoacme-roles-and-personas.md) to understand your team structure
3. Follow the lifecycle phase guides in order as your project progresses

**Starting a new project?**

1. Reference [Project Initiation Guide](octoacme-project-initiation.md) to validate the idea and create your One-pager
2. Move to [Project Planning](octoacme-project-planning.md) once you receive approval
3. Keep [Risk Management & Communication](octoacme-risks-and-communication.md) handy throughout

**Managing day-to-day delivery?**

1. Use [Execution & Tracking](octoacme-execution-and-tracking.md) for sprint workflows and quality standards
2. Reference [Risk Management & Communication](octoacme-risks-and-communication.md) for status reporting and escalations

**Preparing for release?**

1. Review [Release & Deployment Guide](octoacme-release-and-deployment.md) for pre-release requirements and deployment checklists

**Closing out a project or sprint?**

1. Follow [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md) to capture learnings and drive action items

## Key Artifacts

All OctoAcme projects maintain these core artifacts:

- **Project Charter / One-pager** — Problem statement, goals, success metrics, stakeholders, timeline
- **Roadmap and Release Plan** — High-level timeline and release milestones
- **Sprint/Iteration Backlog** — Prioritized, estimated work items with acceptance criteria
- **Risk Register** — Identified risks with impact, likelihood, mitigation, and status
- **Retrospective Notes** — Learnings and action items from project phases or incidents

## Communication Cadence

- **Weekly sync** — PM + Product Manager alignment
- **Twice-weekly standups** — Delivery team progress, blockers, dependencies
- **Monthly stakeholder updates** — Status, risks, upcoming milestones
- **Ad-hoc escalations** — For blockers, security incidents, or critical issues
